# ソースは正しいのに動作が違う

読んでいるソースと、実際に実行されているものが一致しているとは限らない。

## 実行されているものを確かめる

- 実際に読み込まれたファイルを確かめる。Python なら `python -c "import m; print(m.__file__)"`、`python -X importtime`、`sys.path`。
- 実行している版を確かめる。`--version`、パッケージのメタデータ、ビルドの時刻、コンテナのイメージの digest。
- 同じ名前のモジュールやコマンドが複数ないか確かめる (`which -a`、インストール済みの古い版、カレントディレクトリの同名ファイル)。

## 生成物

ソースから生成されるコードやデータ (スキーマからのコード生成、翻訳ファイルのコンパイル、ビルド成果物) は、生成元を直しても生成し直さなければ古いままである。

1. 生成元、生成手順、生成物の対応を特定する。生成物の先頭のコメント、Makefile、生成スクリプトを読む。
2. 実行時に使われているのが生成物であることを確かめる。
3. **生成し直す前に**、現在の生成物と、生成スクリプトの出力を比べる。生成スクリプトの出力は一時ディレクトリへ書く。
   ```bash
   python tools/generate.py --out /tmp/gen-check
   diff -ru app/_generated /tmp/gen-check
   ```
4. 差のうち、生成元の変更で説明できるものは「生成し忘れ」である。説明できない差は、誰かが生成物を手で直した跡である。そのまま生成し直すと、その手入れが消える。
5. 手入れが必要な処理なら、生成元 (スキーマ、テンプレート、生成スクリプトのオプション) へ移してから生成し直す。生成物を手で編集して値だけ合わせることはしない。
6. 生成し直した後、生成物が生成スクリプトの出力と一致することを確かめる。
7. 再発防止として、「生成物が最新か」を確かめるテストか CI の手順を足すか提案する。

## キャッシュ

- ビルドキャッシュ、`__pycache__`、パッケージマネージャのキャッシュ、CDN、ブラウザ、アプリケーション内のキャッシュ。
- キャッシュを消して症状が消えるなら、キャッシュの無効化が抜けている。消して直ったで終わらせず、何が変わったときに無効化されるべきだったかを特定する。
- アプリケーション内のキャッシュは、キーに必要な要素が全部入っているかを見る。キーが足りないと、別の条件の結果を返す (通貨を含まないキーで、別の通貨の値段を返すなど)。

## 設定と環境

- 設定の読み込み順と上書きの規則を確かめる。既定値、ファイル、環境変数、コマンドライン引数、テナント別の上書き。
- 環境変数の違い (`TZ`、`LANG`、`PYTHONHASHSEED`、プロキシ)、ファイルのパーミッション、ディスクの空き、ファイル名の大文字小文字。
- 依存ライブラリの版の違い。ロックファイルと実際にインストールされた版を比べる。
- 動く環境と動かない環境で、これらを一覧にして比べる。違いを一つずつ寄せて、症状が切り替わるものを探す。

## データ

- コードではなく、データ (マスタ、設定ファイル、移行スクリプトの結果) が誤っていることがある。
- データの変更も履歴を調べる。リポジトリ内のデータファイルなら `git log -p` で追える。
- データを直したら、同じ誤りが再び入らないように、読み込み時の検証を足すか提案する。

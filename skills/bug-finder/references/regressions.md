# 以前は動いていた

壊れた変更が分かれば、原因はその差分の中にある。差分は読むより小さくするほうが速い。

## 動いていた版を確かめる

- 「前は動いていた」が本当か、手元で確かめる。タグ、リリース、報告者が使っていた版で、手順 2 の判定コマンドを実行する。
- 動いていた版と壊れた版の両方で判定が期待どおりに分かれることを確かめてから、間を探す。両端の判定が揃わないなら、判定コマンドか前提が誤っている。
- 一度も動いていなかったなら、履歴を探しても見つからない。通常の調査に戻る。

## 差分を小さくする

1. **候補の変更を読む**: `git log --oneline <good>..<bad>` と `git log -p -- <関係するパス>` で、症状に関係しそうなファイルの変更を先に見る。数件なら読めば済む。
2. **二分探索**: 件数が多い、関係するファイルが分からないなら `git bisect` を使う。
3. **コミットの中を絞る**: 見つかったコミットが大きいなら、差分の部分ごとに戻して症状が消える部分を特定する。

## git bisect の使い方

```bash
git bisect start <bad> <good>
git bisect run ./judge.sh
git bisect log        # 判定の記録。報告に使う
git bisect reset
```

判定スクリプトの終了コードの意味は git が決めている。

| 終了コード | 意味 |
| --- | --- |
| 0 | good (症状なし) |
| 125 | skip (この版では判定できない) |
| 1〜127 (125 以外) | bad (症状あり) |
| 128 以上 | bisect 自体を中断する |

- 判定スクリプトは、「症状が出た」と「そもそも動かなかった」を区別する。import エラー、ビルド失敗、依存の欠落は 125 を返す。これを bad として返すと、無関係なコミットを原因と判定してしまう。
- 判定に使うコマンドの終了コードをそのまま返さない。GNU `timeout` はタイムアウトで 124 を返し、これは bad と数えられる。シグナルで止まると 128 以上になり bisect が中断する。スクリプトの中で、症状なら 1、症状なしなら 0、それ以外は 125 に揃えて返す。
- 手動で進めるなら `git bisect good` / `git bisect bad` / `git bisect skip`。
- skip した版があると、結果が「この範囲のどれか」になることがある。その場合は範囲のコミットを個別に読む。
- 判定する値は、具体的な期待値で書く。例: 「北浜→緑ヶ丘 の運賃が 240 なら good」。「テストが通るか」で判定すると、途中で追加・変更されたテストに振り回される。

### 作業ツリーを汚さない

- 未コミットの変更がある作業ツリーで bisect すると、変更を持ち越すか失敗する。`git worktree add <一時ディレクトリ> <bad>` で別の作業ツリーを作り、そこで実行する。
- 終わったら、または中断したら `git bisect reset` と `git worktree remove <一時ディレクトリ>` で片付ける。
- 判定スクリプトは副作用のないものにする。過去の版は、今とは違う宛先へ送信したり、違うスキーマでデータベースを書き換えたりしうる。

### 二分探索が誤る場合

- bisect は good と bad の境界を一つだけ返す。症状が一度直されて後でまた入った履歴では、返った境界が今の症状の原因とは限らない。
- 判定が非決定的なら、各版を複数回実行してから判定する。
- 見つかったコミットの直前と直後で、判定コマンドを実際に実行して結果を並べる。これが報告の根拠になる。

## 見つかったコミットの読み方

- コミットメッセージが説明していない変更を探す。リファクタリングや整形の中に、意味の変わる変更が紛れていることが多い。
- コミットの件名が説明している変更と、症状を起こした変更が別物のことがある。その場合、件名の変更は正しい可能性が高いので、症状を起こした部分に絞って直す。
- データファイル (JSON、CSV、設定) の全面的な書き直しは、差分が大きく見えて要点が埋もれる。値を正規化してから比べる (`jq -S`、並べ替え) と、意味のある違いだけが残る。
- 原因のコミットより後に、同じ箇所を変えたコミットがないか見る。後のコミットは残す前提で直す。

## 報告に入れること

- 原因のコミット (ハッシュと件名)
- 前後の版で判定した結果 (例: 「e2afd79^ では 240 円、e2afd79 では 320 円」)
- 判定できずに飛ばした版と、その理由
- そのコミットの中のどの変更が原因か

# bug-finder

報告された不具合について、症状を説明できる原因を観測と介入で確かめ、原因が生まれた地点で直すエージェントスキルです。同じ原因から出ている別の症状や、同じ書き方の箇所まで調べて報告します。間欠的な失敗、リグレッション、クラッシュ地点と原因が離れているケース、生成物や設定が原因のケース、応急処置にも対応します。

## インストール

[skills](https://github.com/vercel-labs/skills) CLI で入れます。Node.js 22.20 以降が必要です。

```bash
npx skills add 53able/bug-finder
```

エージェントを指定する場合:

```bash
npx skills add 53able/bug-finder --skill bug-finder -a claude-code
```

`-g` を付けると、すべてのプロジェクトで使えるようになります。

## 使い方

「テストがたまに落ちる」「前は動いていた」「結果がおかしい」といった不具合の報告で起動します。「デバッグ」と言わなくても、期待と違う挙動の原因を突き止める作業なら対象です。

網羅的なコードレビュー、性能チューニングだけの作業、新機能の実装には使いません。

同梱の `scripts/repro_rate.py` は、コマンドを繰り返し実行して失敗率を測ります。実行には [uv](https://docs.astral.sh/uv/) が必要です。

```bash
uv run skills/bug-finder/scripts/repro_rate.py -n 30 -- pytest tests/test_x.py
```

## 構成

```
skills/bug-finder/
├── SKILL.md              手順の本体
├── references/           状況別の手引き (間欠的な失敗、リグレッション、範囲の絞り方、原因の起点、コード以外の原因、修正、応急処置、Python)
└── scripts/
    └── repro_rate.py     失敗率の測定
evals/bug-finder/         評価ケース (インストールされない)
```

本体の `SKILL.md` は常に読まれますが、`references/` のファイルは状況に応じてエージェントが自分で開きます。モデルによっては開かないことがあります。

## 評価ケース

`evals/bug-finder/` に 10 件の評価ケースがあります。各ケースは次のファイルからなります。

- `case.yaml`: 期待する結果
- `prompt.md`: エージェントに渡す依頼文
- `place-files.sh`: 作業ディレクトリに課題のプロジェクトを作る
- `check.sh`: 修正結果を機械判定する (一部のケースのみ)
- `graders/`: 報告の内容を判定する観点

評価ケースには模範解答が含まれます。スキルの本体とは別のディレクトリに置いてあり、`npx skills add` ではインストールされません。

評価ケースには、意図的な不具合を含むコードとサンプルデータを収録しています。`fixes-origin-not-crash-site` の `vendor/minitpl` は自作の架空ライブラリです。「上流のリポジトリとの同期」は課題の設定であり、実在の上流はありません。
